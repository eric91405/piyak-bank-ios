# Android 화면 및 실제 사용 흐름 검증 계획

갱신: 2026-09-25. 이 문서는 **검증 시나리오**이며 모든 항목의 통과를 뜻하지 않는다. 실제 결과는 [검증 기록](VALIDATION.md)을 따른다. Android 자동 검사 134개(JVM 83 + 휴대폰 46 + Wear 5)와 최소 API 26의 45개 실행이 통과했다. 실제 TalkBack 주요 조작·최대 OS 글꼴/표시 크기·OS 분할 화면도 확인했다. 스위치 접근은 에뮬레이터 입력 제약으로 환경 차단이며 물리 기기·시계 연결·Play 설치는 별도 단계다.

## 기록 방법과 실행 환경

- 각 실행에 커밋, APK/AAB 종류, 기기·Android 버전, 화면 크기, 글꼴/표시 배율, 권한, 실행 결과와 스크린샷 또는 재현 절차를 기록한다.
- 상태는 `미실행 / 통과 / 실패 / 환경 차단`으로 구분한다. 실패를 수정한 경우 원래 재현 절차와 직접 영향받는 흐름을 다시 확인한다.
- 데이터 변경·삭제 검증에는 새로 만든 QA 기기와 합성 기록만 사용한다. 기존 사용자 기록으로 초기화나 파괴적 오류 주입을 실행하지 않는다.
- MacBook Air의 발열을 고려해 빌드와 에뮬레이터를 동시에 실행하지 않고, 에뮬레이터도 한 번에 하나만 켠다. 실기기에서 동시에 연결해야 검증할 수 있는 휴대폰–시계 통신은 별도로 수행한다.

## 출시를 막는 기능 오류 확인

### 첫 실행과 상태 복구

1. 새 설치에서 시급 기본값, 개인정보 안내, 방 표시와 시작 버튼을 확인한다.
2. 빈 값, 0, 1, 1,000,000, 1,000,001, 매우 긴 입력, 붙여넣기를 검사한다. 유효한 값만 첫 설정을 완료할 수 있어야 한다.
3. 키보드를 연 상태와 가로·큰 글꼴에서 입력창과 시작 버튼에 접근할 수 있어야 한다.
4. 첫 설정을 완료한 뒤 앱 재실행과 프로세스 재생성으로 시급·아이템·설정이 유지되는지 확인한다.
5. 저장소 읽기 실패는 오류와 재시도 화면이어야 하며 기존 데이터를 새 데이터로 덮어쓰면 안 된다. 실제 사용자 저장소는 손상시키지 않는다.

### 근무와 정산

1. 시작 확인의 시급이 설정과 일치해야 한다. 취소는 기록을 만들지 않고, 확인은 근무 하나만 만든다.
2. 일하는 동안 예상 수익·시간이 증가하고, 휴식 중에는 증가하지 않아야 한다. 재개 후 유급 시간만 합산한다.
3. 짧은 근무를 여러 번 정산한 결과와 긴 근무 한 번의 보상 계산을 비교한다. 시급 변경으로 포인트가 달라지면 안 된다.
4. 종료 확인을 취소하면 계속 근무 중이어야 한다. 빠르게 여러 번 확인해도 기록·포인트가 중복되지 않아야 한다.
5. 휴식·근무 상태에서 홈 이동, 화면 잠금, 프로세스 종료, 재부팅 후 복구를 확인한다. 재부팅 사이에 확인할 수 없는 시간이 보상으로 늘어나면 안 된다.
6. 한국 시간 자정과 기기 현지 자정을 각각 넘긴다. 수익의 날짜는 현지 시간, 포인트 한도는 한국 시간으로 표시되어야 한다.
7. 시계 변경·시간대 변경·여러 날의 근무 정산 후 수익과 보상 표시를 확인한다. 이미 지급된 보상이 기록 편집·삭제로 재적립되면 안 된다.

### 꾸미기와 방

1. 전체 81개 항목의 썸네일·한글 이름·가격·분류가 카탈로그와 일치하고 모두 열려야 한다.
2. 전체/우리 방/삐약이/보유함과 각 종류 필터를 조합해 누락·중복·잘못된 선택이 없는지 확인한다.
3. 각 아이템을 미리 본 뒤 취소하면 실제 장착 상태와 잔액이 유지되어야 한다.
4. 잔액 부족 상태의 구매는 비활성화되고 부족 금액이 정확해야 한다. 충분한 합성 잔액으로 구매 확인·취소·성공·재시작을 검증한다.
5. 빠른 반복 구매와 다른 창·시계 상태 변화 중 구매에도 중복 차감이나 음수 잔액이 없어야 한다.
6. 같은 종류를 새로 장착하면 이전 아이템만 해제되고 다른 종류는 유지되어야 한다. 보유함과 실제 방 표시가 일치해야 한다.
7. 81개 모델의 기본 시점·회전·확대에서 뜬 선, 사라진 면, 잘못된 위치, 깜빡임, 과도한 가림을 확인한다. 옷·안경·모자 등의 조합도 검사한다.
8. 놀아주기·배회·가구 상호작용과 설명 문구를 확인한다. 움직임 중지·절전·발열 제한·시스템 동작 줄이기를 존중해야 한다.
9. 탭 전환, 미리보기 종료, 화면 잠금, 다른 앱 이동 시 보이지 않는 3D 화면이 계속 렌더링하지 않아야 한다. GPU 오류 시 사용 가능한 대체 안내가 보여야 한다.

### 기록과 달력

1. 빈 날, 수익이 있는 날, 진행 중 근무, 월 이동, 오늘로 이동, 월 합계를 검증한다. 여러 해의 기록이 있어도 선택한 달만 계산해야 한다.
2. 기존 기록의 수정을 처음 열었을 때 **새 기록 화면이 아니라 해당 기록의 원래 모든 구간**이 보여야 한다.
3. 근무·휴식·시급 변경·자정 통과 구간을 추가하고 수정한다. 부분 원 단위가 하루별/전체 합계에서 정책대로 이어져야 한다.
4. 빈 시급·0원 휴식·상한 초과·같은 시작/종료·역전·미래·겹치는 구간·7일 초과를 검사한다. 오류 때 초안과 원본이 보존되어야 한다.
5. 구간 추가·삭제, 날짜·시간 선택 취소, 키보드 표시, 회전·분할 화면·프로세스 복원을 검사한다. 저장 전 입력이 임의로 사라지면 안 된다.
6. 저장하지 않은 수정 내용이 있을 때 닫기 확인을 검증한다. 저장 성공 전에는 편집 창을 성공으로 닫지 않아야 한다.
7. 두 창에서 같은 기록을 편집·삭제한다. 오래된 revision의 저장·삭제가 최신 기록을 덮어쓰거나 삭제된 기록을 되살리면 안 된다.
8. 수동 추가·수정·삭제 후 포인트·레벨·보유 아이템이 유지되어야 한다.
9. 큰 글꼴에서 달력의 모든 날짜를 선택할 수 있어야 한다. 좁은 화면의 가로 스크롤 안내·발견 가능성과 TalkBack의 전체 날짜·금액 낭독을 확인한다.

### 설정·내보내기·초기화

1. 시급의 유효 범위, 다음 근무 적용, 근무 중 변경 불가를 확인한다.
2. API 33 이상 알림 허용·거부·다시 요청·시스템 설정 변경을 확인한다. 표시 권한과 실제 권한이 다르면 안 된다.
3. 각 알림 간격, 휴식·종료·초기화 후 예약 취소, 재부팅 후 복구를 확인한다. 절전·방해 금지에서의 지연은 별도 기록한다.
4. 근무·포인트 CSV 각각 저장·취소·다른 제공자·저장 실패를 검사한다. 한글, 쉼표, 따옴표, 시간대, 구간, 합계가 정확해야 한다. 선택기 표시 중과 느린 제공자에 저장 중인 상태를 각각 회전·재생성해 선택 형식과 진행 작업이 유지되는지 확인하고 중복 내보내기를 차단한다.
5. 도움말·정책·지원 메일이 열려야 한다. 브라우저/메일 앱이 없는 기기에서도 앱이 종료되지 않아야 한다.
6. 초기화 확인을 취소하거나 다른 문구를 입력하면 데이터를 지우면 안 된다. 합성 QA 데이터에서 정확히 ‘초기화’를 입력하고 확인한 경우만 기록·포인트·아이템·진행 중 근무가 기본 상태로 돌아가야 한다.
7. 초기화 뒤 위젯과 연결 시계에 이전 금액·상태가 남지 않는지 확인한다.

## 연결 기기와 시스템 UI

- 위젯: 빈 상태, 근무·휴식·정산, 날/시간대 변경, 프로세스 종료, 크기 변경, 잠금 해제, 클릭 진입, 마지막 갱신 시각을 검증한다. 초 단위 갱신을 기대하거나 주장하지 않는다.
- Wear OS: 최초 연결, 휴대폰 미설정, 시작·휴식·재개·종료, 승인 응답 대기, 오프라인, 재연결, 연결 노드 변경, 중복/오래된 명령, 양쪽 재부팅을 확인한다. 종료 확인창이 열린 뒤 다른 세션/상태가 도착하면 이전 대상으로 요청하지 않아야 한다. 합성 상태 화면 검사가 실제 페어링·전송 검사를 대신하지 않는다.
- 알림·위젯·시계 표시에는 기록 수정·삭제와 현지 날짜 합계가 반영되어야 한다. 조작 실패를 성공으로 표시하지 않아야 한다.
- Android 접근성 검사, TalkBack 순서, 터치 대상, 색 대비, 키보드/스위치 조작, 동작 줄이기를 각각 확인한다. 단순히 설명 문자열이 있다는 이유로 접근성 통과로 기록하지 않는다.
