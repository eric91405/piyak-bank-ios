# 출시 개선 검증 기록

최근 검증일: 2026-09-21. 기준: PR #2로 병합한 `0cd686d` 이후 TestFlight 사전 검증 후보. 기록 편집 화면의 잘못된 초기값과 다른 창에서 변경·삭제한 기록을 오래된 편집 화면에서 저장하는 문제를 추가로 보완했습니다. 이전 화면·실행 검증은 해당 항목의 설명을 따릅니다.

현재 출시 범위는 근무 기록·포인트·입체 방 꾸미기와 ‘놀아주기’입니다.

## 구현 범위

- 동일 계산기를 iOS/Watch/Widget에서 사용, 휴식 제외, 자정 분할과 원 단위 반올림 손실 수정
- 근무/포인트 정산 한 번 저장, 실패 시 UI 모델까지 복원, SwiftData 기준 세션 복구
- 시급·수익과 보상 분리: 타이머 10분당 100P, 한국 시간 하루 최대 4,800P, 누적 보상 4,800P마다 레벨 상승
- 수정 가능한 급여 기록과 확정 보상 내역 분리, 수동 기록 추가·수정·삭제로 보상 증액 불가
- 측정한 경과 시간과 부팅 식별자로 날짜 변경·중복 적립 방어, 한 근무의 보상 측정은 누적 24시간까지
- 보유 아이템·급여 기록을 유지하는 1회 잔액 전환(1/20, 0~4,800P), 아이템 가격 450~4,000P
- 재실행 가능한 워치 명령 차단, 시급 동기화, 응답 확인, 오프라인 예약 명령 제거
- 무료 81개 포인트 아이템, 기존 보유 내역 보존, StoreKit 경로 제거
- SceneKit 입체 방·병아리·아이템, 새 아이콘과 동일 모델에서 만든 미리보기
- 삐약이를 누르거나 ‘놀아주기’ 버튼으로 인사·장착 가구 상호작용
- 근무 기록 추가/수정/삭제, CSV 내보내기, 로컬 초기화
- 시급/알림 설정 유지, 알림 동의 선택화, 예약 경쟁 상태 제거
- 안내/지원/개인정보 문서, 타깃별 PrivacyInfo, URL scheme

오늘 예상 수익과 보유 포인트는 홈에 표시하며, 날짜별 근무 기록과 수익은 기록 탭에서 확인합니다. 최소 지원 버전은 iOS 17.0 / watchOS 10.0입니다.

## 자동 검증 결과

- **Swift Testing 115개 통과.** 이전 110개에 삭제·초기화 후 남은 편집 화면, 다른 창의 수정 충돌, 정상 수정·삭제, 같은 ID의 분리된 모델을 다루는 실제 디스크 저장소 테스트 5개를 추가했습니다.
- 기록 편집·삭제 확인은 영속 모델 대신 ID와 원래 구간을 보관합니다. 저장 직전에 현재 기록을 다시 조회하므로 다른 창에서 삭제하거나 변경한 기록을 덮어쓰거나 저장 성공으로 잘못 표시하지 않습니다. 꾸미기 상세도 표시할 값을 복사해 초기화 후 삭제된 카탈로그 모델에 접근하지 않습니다.
- **실제 초기 버전의 SwiftData 스키마 업그레이드 검증 통과.** `c70a8be`의 모델 원본으로 별도 실행 파일에서 만든 저장소를 현재 코드로 이전했습니다. 근무 3개·보유/장착 6개·기존 원장 4개와 원래 구간 JSON이 보존됐고, 63,997P→3,199P 전환은 한 번만 적용됐습니다. 진행 중 근무를 빈 설정에서 복구한 뒤 새로 측정한 10분에만 100P가 적립됐으며, 별도 프로세스 재실행 후 3,299P와 보상 영수증 2개가 유지됐습니다. 이전 원본 DB/WAL도 변경되지 않았습니다. [검증 스크립트 설명](../scripts/legacy_schema/README.md)에 재현 방법과 한계를 기록했습니다. macOS SwiftData를 사용한 합성 저장소 시험이며 실물 iPhone의 배포 서명 업그레이드를 대체하지 않습니다.
- 여러 iPad 창이 앱 전체의 근무 서비스를 공유합니다. 별도 컨트롤러가 생겨도 시작 전에 저장소를 확인해 두 번째 활성 근무를 만들지 않습니다. 이미 중복된 활성 기록은 최근 근무를 이어가고, 이전 기록의 열린 구간은 다음 근무 시작 시점에 닫아 보관합니다. 겹친 보상은 합집합으로 한 번만 인정하며, 복구 실패 시 모든 기록과 보상 원장을 원상 복원합니다. 실제 iPad 두 창 UI 조작은 이번 검증에 포함하지 않았습니다.
- 시계 보정 후 종료·휴식·재개가 막히지 않도록 급여 구간의 상대 시간을 유지하며 현재 시각에 맞춥니다. 새 기준점은 기존 보상 JSON의 선택 필드이므로 SwiftData 모델 필드를 추가하지 않습니다. 완료·수동 기록과 보상 날짜는 이동하지 않습니다. 진행 중 기록의 날짜별 귀속은 보정된 시각을 따르며, 재부팅으로 측정할 수 없는 시간은 보존된 체크포인트까지만 복구합니다. 소수 밀리초·최대 시급의 반올림과 저장 실패 후 재시도도 검사했습니다.
- 위젯의 완료 수익은 각 시간대의 자정별 합계로 저장합니다. 기록별 원 단위 이월을 유지하면서 기록 원문을 전송하지 않고, 1,000개 기록의 페이로드가 8KB 미만임을 검사했습니다. 서울↔UTC/미국 이동, DST, 자정, 비그레고리력, 전체 시스템 시간대의 계산 일치를 확인했습니다. 구형 스냅샷의 출처 불명 완료 합계는 iPhone 재동기화 전까지 0으로 처리하며 근무 기록은 보존합니다.
- 구형 `piyak.<sessionID>.periodic/milestone.*` 알림도 취소·업데이트 시 정리하며 다른 알림은 보존합니다. 워치의 상태 요청은 저장소 복구·체크포인트·알림 보충을 함께 호출합니다. 15분 간격의 48개 예약 소진 이후 새 예약이 채워지는 경로를 합성 클라이언트로 검증했습니다.
- 미래 시각이 담긴 구형 워치 캐시도 최초 신규 형식 상태로 전환됩니다. 전환 후에는 지연된 구형 상태가 최신 상태·초상화를 덮지 못하도록 차단하며, 캐시 저장·재실행 뒤에도 같은 규칙을 검사했습니다.
- 저장소 이전은 SQLite backup API로 미반영 WAL까지 포함한 일관된 복제본을 만든 뒤 게시합니다. 이전 실패·재시도·빈 공유 파일·복수 이전 저장소 충돌을 검사하며, 실패 시 오래된 복사본으로 돌아가거나 빈 DB를 여는 경로를 제거했습니다. 실제 디스크 SwiftData 테스트에서 기록·보유/장착·잔액·보상 전환 마커와 새 저장소의 후속 쓰기를 재실행 후에도 유지했습니다.
- 이전 저장소 사본은 업그레이드 동안 보존하며, 사용자가 ‘모든 데이터 삭제’를 선택할 때 사본과 중단된 이전 작업의 잔재도 정리합니다. 현재 저장소·WAL은 정리 대상에서 제외하고, 정리 실패 시 현재 근무·잔액을 삭제하지 않습니다.
- 알림은 시스템의 실제 pending 요청과 대조합니다. 권한 재허용, 부분 예약 실패, 예약 소진, 재진입·재실행의 주기 보존, 일시정지/재개 중 취소 이후 완료된 비동기 예약 정리를 검증했습니다.
- 워치는 상태와 이미지를 분리 전송하고 장착 목록·렌더러 버전으로 연결합니다. 이미지 선도착→종료→상태 도착, 오래된 이미지, 동일 스냅샷 시각의 장착 상태 역전, 발행 시계 후퇴와 구버전 호환을 검사했습니다. 실물 기기의 백그라운드 전송 검증과는 구분합니다.
- 시급 10,000원/1,000,000원의 동일 시간 보상, 휴식 제외, 짧은 세션의 소수 포인트 합산, 중복 시간 합집합, KST 자정·일일 한도·윤일·DST 경계를 확인했습니다.
- 수동 근무 추가·연장·삭제 후 재추가로 보상이 늘지 않으며, 보상 이후 구매·기록 삭제가 당일 적립 한도를 되돌리지 않는지 검증했습니다.
- 시스템 날짜 변경과 앱 상태 저장 후에도 같은 부팅의 일일 한도가 유지되고, 재부팅 이후 uptime이 이전 값보다 커도 새 날짜를 인식하는지 검증했습니다. 재부팅 전 저장한 측정 구간을 유지하고 측정 불가능한 공백을 추가 보상하지 않습니다.
- 실패한 정산·전환의 원장/실시간 모델/보상 시계 복원, 전환 재실행·정상 초기화 뒤 재적립·오래된 컨트롤러의 중복 종료를 검사했습니다.
- 정수 시급, 휴식, 자정 분할, DST, 1,000개 소수 밀리초 구간의 금액 보존, 예전 스냅샷 호환성을 검증했습니다.
- 강제 저장 실패 시 정산·구매·장착·기록 수정·삭제·초기화의 원장과 화면 모델 복원을 확인했습니다.
- 근무 상태 복구, 중복/만료/다른 세션 워치 명령 차단, 설정 유지, 기존 정산 보정의 재실행 안전성을 확인했습니다.

## 직접 확인한 동작

- 2026-09-21 새 iPhone 17 Pro Max / iOS 26.5 테스트 기기: 온보딩에서 시급 0원·1,000,001원은 차단하고 10,000원은 허용했습니다. 근무→휴식 중 41원 상태가 시뮬레이터 종료·덮어 설치·재실행 후 유지됐습니다. 재개→종료 후 홈·월 합계·당일 기록의 수익 75원과 별도 보상 4P가 일치했습니다. 줄무늬 티 상세의 750P 가격·4P 잔액과 ‘746P 더 필요해요’ 구매 차단도 확인했습니다.
- 같은 기기에서 기존 기록 수정을 눌렀을 때 새 기록 추가 화면이 열리는 오류를 재현하고 수정했습니다. 최종 빌드에서 기존 근무·휴식·근무 3개 구간이 올바르게 열렸으며 첫 구간 시급을 수정하자 1개 기록의 수익만 75원→117원으로 바뀌고 포인트는 4P로 유지됐습니다. 이어서 새 기록 추가는 별도의 기본 초안으로 열렸습니다. 설정의 상한 초과 시급은 저장을 막았고 정상 시급 15,000원은 저장됐습니다. 앱 재실행 후 수익 117원·4P·기본 시급 15,000원이 유지됨을 확인했습니다.

## 행동·모델 검증

- `ValidateScene.swift`: 단품 81개 + 장착 장면 81개 + 전체 착용 조합 9개, 총 171개 장면을 검사했습니다. 좌표·메시·모서리 반경·카메라 범위·실제 썸네일 검사에서 오류 0개, 검토 경고 0개입니다. [조합 렌더링](quality/room-combinations.jpg)을 직접 확인했습니다.
- `ProbeRoomBehavior.swift`: 실제 SceneKit 행동 시계를 전진시켜 물주기·피아노·강아지·소파·독서를 확인했습니다. 새 터치 반응 순환, 빠른 8회 연속 터치 거부, 반응 후 자동 행동 복귀, 착석 중 터치와 근무 상태 변경 시 안전한 하차, 이동 범위, 일시정지/종료를 검사했고 3개 방에서 오류 0개입니다. 화면이 없는 검사 환경에서도 새 행동을 반영하도록 SceneKit transaction을 명시적으로 갱신했습니다. GPU 캡처는 총 8회 이내로 제한했습니다. [실제 행동 프레임](quality/room-activities.jpg)은 합성 목업이 아닌 엔진 렌더링입니다.
- 행동 선택과 경로 검증은 장착한 가구·소품, 안전한 이동 범위와 일시정지를 다룹니다.
- 생성 미리보기에는 원본 모델·생성기 파일의 SHA-256 지문을 기록하고 CI에서 대조합니다. 모델을 바꾸면 이미지도 다시 생성해야 검사에 통과합니다.

[실제 화면 캡처](screenshots/): iPhone 1320×2868, iPad 2064×2752. 원본 시뮬레이터 화면을 크기 변경 없이 JPEG로 내보냈으며 합성 목업이 아닙니다. 홈의 시간 보상 안내, 상점 및 아이템 미리보기의 새 가격으로 iPhone 캡처 3장을 갱신했습니다. iPad 및 접근성 다크 모드 이미지는 모델 개선 이전의 QA 참고용입니다.

발열을 줄이기 위해 로컬 검증은 낮은 프로세스 우선순위·직렬 작업과 냉각 간격을 적용하며, 빌드 중 시뮬레이터를 종료하고 화면 점검 때 iPhone 한 대만 실행합니다. 전체 Release 빌드는 원격 GitHub Actions에서 확인합니다. 이번 검증의 macOS 발열 상태는 `nominal`이었으나 새 시뮬레이터의 초기 부팅 중 CPU 사용률과 메모리 압력이 상승해 종료·냉각 후 재개했습니다. 이는 실제 온도 측정값은 아닙니다.

시간 측정은 잠자는 동안에도 흐르는 [Apple의 monotonic clock](https://developer.apple.com/documentation/kernel/1646199-mach_continuous_time)을 사용하며, 경과 시간 계산 목적의 개인정보 매니페스트 사유 `35F9.1`을 포함합니다. 서버가 없는 앱이므로 기기 재부팅과 날짜·저장소 조작을 결합한 공격이나 실제 근무 여부까지 증명하지는 않습니다.
