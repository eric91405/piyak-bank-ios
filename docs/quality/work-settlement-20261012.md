# 근무 종료·포인트 안내 점검 — 2026-10-12

## 제보와 확인 범위

App Store iPhone 앱에서 종료 안내와 실제 적립량이 달라 보였다는 제보를 받았다. 당시 근무 시간과 양쪽 포인트 수치는 기억하지 못한 상태여서, 제보와 동일한 계산 불일치를 재현하거나 원인을 확정하지는 못했다. Android 변경은 없다.

기존 코드는 종료 안내에 정산 함수가 반환한 적립 합계를 표시했다. 기존 회귀 테스트 115개에서도 적립량과 원장 잔액 증가분의 차이는 발견되지 않았다. 계산 정책을 임의로 바꾸지 않고, 아래 확인된 표시 혼동과 종료 대상 문제를 보완했다.

## 변경

- 정산 결과를 단일 정수 대신 실제 원장에 삽입한 날짜별 적립 내역과 정산 전·후 잔액으로 반환한다. 저장이 성공한 뒤에만 홈에서 완료 안내를 표시한다.
- 종료 안내에 **이번 총 적립량**과 **보유 포인트의 전·후 값**을 함께 표시한다. 여러 날짜에 걸친 근무 또는 이전 날짜에만 적립되는 근무는 KST 날짜별 내역도 표시한다.
- 홈의 ‘오늘 받은 꾸미기 포인트’를 ‘오늘 근무로 적립된 포인트’로 바꾸고, KST 근무 날짜별 합계라는 설명을 추가한다. 자정을 넘겨 종료하면 총 적립량과 오늘 몫은 다를 수 있다. 예: 23시~다음 날 01시 근무는 총 1,200P, 각 날짜 600P다.
- 종료 전 안내에 6초당 1P와 같은 날의 짧은 근무 합산을 명시한다. 10분당 100P·날짜별 4,800P 규칙과 동일하다.
- iPhone 종료 확인창이 열린 뒤 워치나 다른 창에서 해당 근무를 종료하고 새 근무를 시작해도, 오래된 확인으로 새 근무를 종료하지 못하게 한다. 이미 끝난 근무에 다시 확인하면 0P 성공 안내를 표시하지 않고 상태 변경을 알린다.
- Watch 종료 확인도 창을 열 때의 대상 근무 ID를 보존한다. 명령의 유효 시간은 실제 확인 시점부터 계산한다.

저장 모델과 보상 정책은 기존 형식을 유지한다. 수동 기록·수정·삭제, 구매, 이전 정책 잔액의 처리 규칙도 유지한다. App Store 업로드·배포는 수행하지 않았다.

## 자동 검증

Xcode 26.6 / Swift 6.3.3, 한 번에 한 컴파일 작업으로 실행했다.

| 검증 | 결과 |
|---|---|
| `swift test --jobs 1` | 기존 115개와 새 정산 회귀 9개, 총 **124개 통과** |
| 실제 저장소 재개방 | 정산 안내의 잔액·날짜별 원장 내역 일치 |
| 구버전 실제 SwiftData 스키마 이전 스크립트 | 기록·아이템·잔액 이전, 별도 프로세스 복구·100P 정산·재실행 보존 통과 |
| iPhone·Watch·위젯 Release 빌드 | 기기용 및 시뮬레이터용 통합 빌드 통과 |
| 리소스 검사 | 미리보기 81개·아이콘 4개·개인정보 매니페스트 3개·URL scheme 통과 |
| `git diff --check` | 통과 |

추가 회귀는 구매·이전 정책 거래가 있는 잔액, 자정 분할, 이전 날에만 근무 후 휴식 중 종료, 하루 한도·0P, 짧은 근무 합산·휴식·복구, 오래된 종료 확인, 이미 종료된 근무, 저장 실패·재시도, 디스크 저장소 재개방을 검증한다.

빌드에는 AppIntents 의존성이 없어 메타데이터 추출을 건너뛴다는 경고가 있었고, 컴파일 오류는 없었다.

## 실제 화면 검증

기존 기기 데이터와 분리한 새 iPhone 17 Pro / iOS 26.5 QA 시뮬레이터에 Release 사본을 설치했다. unsigned 사본은 App Group 권한이 없어 시작을 실패했으며, 앱·위젯·Watch 사본에 원본 entitlement를 포함한 로컬 ad hoc 서명을 적용한 뒤 검증했다. 이 실패를 배포 앱의 저장소 문제로 취급하지 않는다.

- 온보딩 → 시급 10,000원으로 근무 시작 → 휴식 → 재개 → 종료 확인 → 정산 안내를 실제 조작했다.
- 휴식 중 예상 수익은 16원으로 유지됐다.
- 완료 안내는 **총 5P**, **보유 포인트 0P → 5P**를 표시했고, 뒤쪽 홈 잔액과 오늘 적립도 **5P**로 일치했다.
- 앱 종료·재실행 후에도 **5P**, **오늘 예상 수익 86원**, 근무 대기 상태가 유지됐다.
- 빌드와 시뮬레이터 실행을 겹치지 않았다. 검증 후 이번에 만든 QA 기기만 종료·삭제했다.

Watch의 확인 대상 보존은 소스 검토와 통합 빌드로 확인했으며, 이번 작업에서 실제 iPhone–Watch 연결 조작은 하지 않았다. 자정·한도·저장 실패 등은 자동 회귀 결과이고 실제 장시간 근무 시험을 대신하지 않는다. 사용자 제보 당시의 동일 증상과 물리 기기 검증은 미확인이다.

이번 테스트와 빌드 로그는 `/tmp/piyak-settlement-tests.log`, `/tmp/piyak-settlement-build.log`, `/tmp/piyak-settlement-simulator-build.log`, `/tmp/piyak-settlement-migration.log`에 있다. 임시 파일이므로 장기 보존을 보장하지 않는다.
